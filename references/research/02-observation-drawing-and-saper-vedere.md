# Observation, Drawing, and Saper Vedere

## Grounding

The [Britannica excerpt](../sources/articles/britannica-leonardo.md) describes visual experience as central to Leonardo and uses the phrase *saper vedere*, translated there as knowing how to see. It is the encyclopedia's account, not a verified standalone Leonardo quotation.

The [Met essay](../sources/articles/metmuseum-leonardo.md) explains drawing as a record of investigation and discusses studies of poses, stage settings, anatomy, plants, water, and birds. It is a stronger local basis for this method than the notebook catalog, which contains no actual notebook pages.

## Observation as active comparison

Modern application begins by separating the visible object from the label assigned to it. Record what was actually seen or measured, the viewpoint, and what remains an inference. Compare variants or repeat an observation when one view could conceal the relevant relation.

A sketch can expose an omitted connection, mistaken proportion, unexplained transition, or assumed sequence. It is useful when it makes thought inspectable; artistic polish is optional. For nonvisual problems, a concrete example, dependency table, or sequence can serve the same purpose.

## Work across scales

Move between detail and whole. A local interaction can look clear while the complete task is incoherent. A polished overall composition can conceal an inaccessible control. Ask which level of analysis explains the user's actual difficulty.

Use a comparison set only as large as needed to discriminate between explanations. Repetition without a question can become delay. Set an appropriate stopping condition: what observation would be enough to choose the next step?

## Evidence versus rendering

A convincing generated image can depict something never observed. A rough diagram can faithfully expose uncertainty. Label observations, proposed designs, and illustrative reconstructions separately. Do not present a visual artifact's polish as validation.

Keep records that can be revisited: screenshots, sketches, field notes, or observed sequences. Do not infer that all domains are visual or that a diagram resolves a question about meaning or values by itself.

## Hypothetical application

A team calls an interface premium. Compare screenshots and a real task sequence: what guides attention, how transitions work, and where a user hesitates. Try an alternative that changes one suspected relation. The diagnosis remains provisional until evidence discriminates between hierarchy, familiarity, content, and other explanations.
